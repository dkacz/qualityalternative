BLOCKER — Import-time invalid or rejected Agent Inbox imports leave the review row READY, preserve the stale reviewed fingerprint, and keep import/priority controls visible instead of converting the package to a finite invalid review item.
Exact claim: A Drive package whose content bytes change after review is correctly rejected by AgentInboxPackageImporter, but MainViewModel.applyAgentInboxImportResult() does not update the corresponding AgentInboxReviewCandidate; it only records analytics and sets latestMessage. The candidate remains in agentInboxCandidates with its previous status == READY, previous reviewedContentSha256, previous reviewedContentSizeBytes, and any accepted priority state.
Why vulnerable: This violates the R3 recheck target that changed bytes for the same Drive folder/content name must not retain a stale fingerprint, and it contradicts the PRD requirement that unavailable or invalid packages become finite visible review items and are not misleadingly importable. The user-facing result is a package that has just failed validation as changed-after-review but still renders through the READY UI branch with Accept priority/Priority accepted, Remove, and Import; repeated import attempts are possible without a rescan, and the UI state falsely represents the old reviewed fingerprint as still authoritative. The same state-transition defect applies to import-time oversize content routed through CONTENT_FILE_TOO_LARGE, manifest SHA mismatch, repository REJECTED results, and non-size import download failures, because those paths either enter the same INVALID/REJECTED branch or fall through the generic import catch without mutating the candidate row.
