Severity: BLOCK — Existing Sprint 27 app-created Agent Inbox folder ids can bypass the new Picker flow and keep scanning the wrong folder.
Exact claim: The Sprint 28 implementation does not prove that a persisted agentInboxDriveFolderId came from the Sprint 28 Google Picker folder-selection grant before using it for AGENT_INBOX_SCAN.
Why it is vulnerable: The shipped lane history records that Sprint 27 fixed prior blockers with “first-connect folder creation with persisted id,” and the post-release diagnosis says externally uploaded rclone packages were invisible while the app reported “connected, no packages found” under drive.file. In the current code, Settings chooses non-Picker AGENT_INBOX_SCAN whenever state.agentInboxDriveEnabled && !state.agentInboxDriveFolderId.isNullOrBlank(). Persistence stores only agent_inbox_drive_enabled and agent_inbox_drive_folder_id; grantMode=pickerFolder is recorded only as an analytics event and is not durable connection state. Therefore, an upgraded install with a Sprint 27 app-created folder id can continue to scan that app-owned folder under non-Picker authorization, never force the user to select the externally populated rclone folder, and reproduce the original invisibility failure.
